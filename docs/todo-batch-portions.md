# 备餐按份统计重构 TODO

当前 `develop` 已完成食物/记录的 g、ml 双单位模型；备餐仍按克统计，并在内部暂时把
`1ml` 当作 `1g`。本分支用于长期替换该临时方案。

## 目标

- 备餐保存总份数，不再依赖总克数计算剩余量。
- 每次记录保存消耗份数，剩余份数 = 总份数 - 已记录份数。
- 食材仍保留 g / ml 数量和营养数据，仅用于展示与计算每份营养。
- 删除备餐中的 `1ml = 1g` 假设。

## 数据模型草案

- `MealPrepBatchMeta` 增加 `totalPortions`，弱化 `totalGrams` / `portionGrams`。
- `FoodEntry` 增加备餐关联和 `portionCount`。
- 备餐每份营养使用快照，避免食物库变化影响历史。
- 旧备餐按 `totalGrams / portionGrams` 迁移为总份数。
- 食物库 JSON / 全量备份按需升级版本并保留旧格式兼容。

## UI 改动

- 新建备餐：输入总份数，食材仍按 g / ml 录入。
- 记录备餐：输入份数，不再输入克数。
- 剩余量、自动移除、分享卡统一按份展示。

## 验收

- 混合 g / ml 食材的备餐不再需要任何密度假设。
- 旧备餐和旧饮食记录可迁移且不丢数据。
- 编辑 / 删除备餐记录后剩余份数准确。
